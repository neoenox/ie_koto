## ストア掲載文

### 短い説明（80字以内）

```
家の「あれやらなきゃ」を、家族で共有。終わらせると次の1件が出る、家のやることリスト。
```

### 詳しい説明（4000字以内）

```
家の「あれやらなきゃ」を、忘れない。家族で使う、家のやることリストです。

気づいたときに、タイトルだけで放り込めます。担当も期限も後でよい。終わったら丸を1タップ、間違えたらその場で取り消せます。

■ 家のことが、勝手に回る
・定期の案件は、終わらせると次の1件が自動で出てきます（毎日／毎週◯曜／終わってからN日ごと）。「エアコンのフィルターそうじ」を次にいつやるか、覚えておかなくて大丈夫です。
・終わった記録は自動で溜まります。数年住むと同じ案件の前回・前々回が、そのまま家の記録になります。

■ 家族で同じ画面を見る（任意）
・1人で使うなら、何も要りません。サーバーに一切つながりません。
・2台以上で共有したいときだけ、世帯のシートから「つくる／はいる」でつなぎます。変更は上書きせず操作ログとして追記し、どの端末でも同じ結果になります。
・アプリを入れていない相手には、1件だけのURLを送れます。相手はブラウザで開いて「やる」を押すだけ（インストールもアカウントも不要）。リンクは7日で失効します。

■ 使い方はシンプル
・ホームは「今日」と「これから」。
・追加は、打ってEnterで登録完了。だれ・いつは後から。
・詳細には「だれが・いつまで・くりかえし」と、これまでのやりとり。
・「おわったもの」で、終わったことが新しい順に見られます。

■ やらないこと
分担のグラフ、ポイント、ランキング、時給換算、達成率、家計簿、カレンダー、買い物専用画面、広告。余計なものは入れていません。

■ 記録の扱い
個人ログインやパスワード、メールアドレス、電話番号、連絡先、位置情報、広告IDは扱いません。アナリティクスや広告のSDKも入れていません。詳しくは下のプライバシーポリシーをご覧ください。

※ 初回起動時は、よくある家庭の案件（牛乳・保育園の書類・ゴミ出し・エアコン・電球・水道・子供の靴・お風呂そうじ）が入った状態で始まります。2回目以降はその続きから始まり、デモを入れ直しません。
```

### 新機能（What's new）

```
最初の版です。ホーム／追加／詳細／おわったものと、「家族とつなげる」シートを入れてあります。
```

## ストア申告（データセーフティ）

[PRIVACY.md](PRIVACY.md) の「Google Play のデータ申告との対応」と一致させる。申告内容：

- **収集するデータ**: アプリ内のコンテンツ（用事・コメント）／氏名（表示名）／デバイスまたはその他のID（端末ID・世帯ID）。
- **目的**: アプリの機能、同期。
- **送信先**: 自前の同期サーバー（Cloudflare Workers + D1、任意）。第三者への販売・広告目的の提供はしない。アナリティクス・広告SDKなし。
- **暗号化**: 通信はHTTPS（本番公開時）。
- **削除**: 世帯の削除・端末データの消去で可能。
- **広告**: なし。**対象年齢**: 全年齢。**アプリ内課金**: なし。

## 初回起動のデモ（公開仕様として確定）

- **初回だけ**、よくある家庭の案件が入った状態で始まる（牛乳を買う・保育園の書類を書く・ゴミ出し・エアコンのフィルターそうじ・廊下の電球を交換する・水道から変な音がする・子供の靴を買う・お風呂そうじ）。端末に保存され、**2回目以降はその続きから始まり、デモを入れ直さない**。
- 世帯に接続すると別の領域で始まり、デモは表示されない。
- **テスト世帯の資格情報はビルドに埋め込んでいない**。同期の資格情報は `--dart-define`（`IE_KOTO_API`/`IE_KOTO_HOUSEHOLD`/`IE_KOTO_TOKEN`）で渡すときだけ有効で、既定は空（[lib/sync/config.dart](../lib/sync/config.dart)）。
- デモを出したくないビルドは `--dart-define=IE_KOTO_NO_DEMO=true`。
- 根拠：[lib/main.dart](../lib/main.dart)（`noDemoSeed` と同期設定の分岐）、[lib/store.dart](../lib/store.dart)（`IssueStore.demo`）。

## 内部テスト配布（所有者作業）

全体の順番と止める条件は [RELEASE_RUNBOOK.md](RELEASE_RUNBOOK.md) の D。ここは配布の手順のみ。

1. Play Console に初回登録（開発者契約・本人確認・支払い）。
2. アプリを作成し、Play App Signing を有効化。アップロード鍵は既存の鍵（アップロード証明書SHA-256 `5F:1D:…:36`、`CN=ie_koto`）を使う。照合手順は [ANDROID_RELEASE.md](ANDROID_RELEASE.md)。
3. 署名済みAAB `build/app/outputs/bundle/release/app-release.aab`（Gitには含めない）を内部テストのトラックへアップロード。
4. テスターを追加して配布。掲載文・素材・データ申告はこの文書どおりに入力する。
5. 配布後、実機で保存・終了復帰・同期を確認（#60）。
