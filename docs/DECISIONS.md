# 設計の判断

市場調査の結論（[VALIDATION.md](VALIDATION.md)）を、そのまま実装のルールに落としたもの。

## 調査から決まった3つのこと

1. **UIの最小化は必須条件で、差別化にはならない**
   標準のリマインダー・Google Keep・LINEは無料で最小。だから軽さで勝負せず、軽さは「前提」として作り、勝負は別の場所に置く。
2. **勝負するのは2つだけ**
   - 定期の案件が勝手に次へ進む（完了 → 次の1件が自動生成）
   - 終わった記録が勝手に溜まる（同じ案件の前回・前々回）
   この2つ以外は、便利でも入れない。
3. **相手がアプリを入れなくても使えること**
   調査で最も重い壁は「パートナーがインストールしない」だった。この版は**招待もログインも同期も要求しない**。1人で開いて、1人で使える。

## UI予算（追加するときに必ず守る）

1. 1画面の主操作は1つ（ホーム＝追加、詳細＝おわった）
2. 追加の必須項目はタイトルだけ
3. 一覧のカードは最大2行
4. 一覧に出す情報は最大2つ（期限・担当・くりかえしのうち上位2つ）
5. 通常操作でモーダルを連ねない（属性は1枚のシートで完結）
6. ナビゲーションは0〜3（この版は下部タブなし。ホーム・詳細・おわったものの往復だけ。世帯の設定はシートで済ませる）
7. 色で意味を持たせすぎない（期限切れの1箇所のみ）
8. グラフ・カレンダー・達成率をホームに置かない
9. 「チケット」「ステータス」「優先度」「プロジェクト」を使わない
10. 高度な機能は詳細の中に隠す（対応待ち・繰り返し・削除・名前の変更）
11. 1回の完了は1タップ、取り消しはその場で
12. 新規登録は3秒（打ってEnter）

追加を判断するときの合言葉は「**それを足してもホームの情報量は増えないか**」。

## 禁止リスト（初期版では入れない）

家計簿、カレンダー、チャット、買い物専用画面、ポイント、ランキング、達成率、家事時間の測定、時給換算、貢献度グラフ、AI担当割当、細かいカテゴリ、タグ、サブタスク、ガントチャート、部屋管理、在庫管理、広告。

これらは既存の家事アプリが実装し、そして「開くのが面倒」を作った機能群である（[VALIDATION.md](VALIDATION.md) 1-2 / 1-6）。

## 画面に出す言葉（これ以外の言い方をしない）

- 状態: **やること / おわった**。例外として詳細の中だけ「対応待ち」
- 担当: **自分 / パートナー / だれでも**
- 期限: **今日 / 明日 / M/D / M/Dまで（過ぎたとき）**
- 定期: **毎日 / 毎週 火・金 / 終わってから60日ごと**
- セクション: **今日 / あとで**

## 内部の作り（見せない部分）

| 内部（仕事の用語） | このアプリでの扱い |
|---|---|
| Issue | 1件のやること。番号は画面に出さない |
| assignee / reporter | だれが / 追加した人 |
| dueDate | いつまで |
| status: open, doing, waiting, done | やること / 対応待ち / おわった |
| recurrence | くりかえし。完了すると、決定的なid（`next:<完了opId>`）で次の1件が射影から出る |
| seriesId | 同じ定期案件のまとまり。前回・前々回の計算に使う |
| comments / attachments | 「これまで」の並び |
| activity（履歴） | 追加・担当変更・期限変更・状態変更・完了・取り消し |
| op（操作ログ） | 内部の持ち方。変更は上書きせずにopとして追記し、射影し直して画面に渡す。書いた人（`member`）もopに残る（[SYNC_DESIGN.md](SYNC_DESIGN.md)） |
| 同期 | 追記したopを、そのままサーバーに預ける（opの出し入れ2本＋世帯の始末2本。[server/](../server/README.md)）。サーバーはopを解釈せず、突き合わせは端末側の射影だけが決める |
| 保存 | opの列・端末id・送信済み位置・この端末の人と表示名を端末に残す。**射影は残さず、起動時にopから作り直す**（[SYNC_DESIGN.md](SYNC_DESIGN.md) §8） |
| 1件リンク | アプリを入れていない相手に送るURL。相手のブラウザでは**「見る・やる・あとで」の3つだけ**。世帯のほかの案件は渡さず、端末にも何も残さない。7日の期限付き（[SYNC_DESIGN.md](SYNC_DESIGN.md) §8.6） |
| 世帯の画面 | ホーム右上の世帯名から開くシート。作成・参加・招待・再発行・削除／この端末の人と表示名／書き出し・読み込み。ホームの情報量は増やさない |

定期案件は「次を出す」ことで、誰が何回やったか・最後はいつかが自然に残る。集計画面は作らない（見たい人だけが見る、という前提の前に、まずホームに出さない）。

## この版でやっていないこと

- 保存の中身の暗号化（書き出し／読み込みによる引っ越しは、世帯のシートからできる）
- OSの通知（アプリ内のお知らせ1行と、起動時同期後の担当通知までは済み。設計の3種「朝の要約・期限当日・自分の担当になった瞬間」に対応）
- 写真の取り込み（履歴の表示枠は画面側にあるが、opが無いのでデモには出していない。当面しない方針は [SYNC_DESIGN.md](SYNC_DESIGN.md) §10 の通り）
