# release実機受入（#60）

`release`版をAndroid実機で受け入れるための手順と記録用紙。
自動テスト（`integration_test/app_flows_test.dart`）とエミュレータdebug E2Eは合格済みだが、
実機の代替にしない。1項目でも不合格・未実施が残れば #60 は閉じない。

## 前提

- #59 の署名済みrelease成果物（AAB/APK）が用意されていること。
- 実機は2台あることが望ましい。1台のみの場合は「2台同期」を未実施として残す。
- テスト用の世帯・記録を使う。本番の世帯・実データを触らない。

- 端末2（機種/OS/ビルド番号）： / アプリversion：
- 成果物（AAB/APK・署名指紋の照合結果）：

## 受入項目

凡例：○ 合格／× 不合格（Issue化）／− 未実施（理由を書く）

### R1 追加・完了・コメント後の強制終了と再起動
- [ ] 用事を追加し、コメントを付けて完了する
- [ ] 設定→アプリ→強制停止し、再起動する
- [ ] 追加・コメント・完了状態がすべて復元されること
- [ ] 保存完了前の強制終了（連打直後など）では、欠けた分が分かる範囲で記録すること
- 判定：

### R2 オフライン編集→再起動→回線復旧
- [ ] 機内モード等でオフラインにし、追加・改名・完了・メンバー追加を行う
- [ ] そのまま再起動する
- [ ] 回線復旧後、未送信・名簿・担当・本人設定が維持され、同期されること
- 判定：

### R3 2台での収束（2台ある場合）
- [ ] 両端末で追加・完了・改名・メンバー追加を同時期に行う
- [ ] 両端末とサーバーで記録が一致し、重複・欠落がないこと
- [ ] 1台のみの場合は本項目を「− 未実施（端末不足）」とする
- 判定：

### R4 背景停止・前面復帰・通信失敗と再試行
- [ ] アプリを背景に回し、しばらく置いてから前面に戻す。相手端末の変更が取り込まれること
- [ ] 通信失敗時（サーバー停止・圏外）に未送信が残り、復旧後に自動再試行されること
- 判定：

### R5 世帯切替の分離
- [ ] 別の世帯に参加・切替し、記録・未送信・本人設定が混ざらないこと
- [ ] 元の世帯に戻すと元の記録が残っていること
- 判定：

### R6 継続利用の所感（数日利用後）
- [ ] 分かりにくい操作・誤操作・同期の不整合があれば記録する（なくても「なし」と書く）
- 記録：

## 終了条件

- R1〜R5がすべて○、または×はIssue化して #60 に紐付けること。
- 未実施（−）が残る場合、その範囲を #60 に明記すること。
- 結果の要約を #60 のコメントに貼り、証跡とする。
- 実機受入がすべて合格し、未解決の阻害不具合がないことが #60 の解除条件。
