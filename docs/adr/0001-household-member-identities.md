# ADR 0001: 世帯内の安定したメンバーID

状態: 採用

## 背景

固定文字列 `me` / `partner` はアプリ利用者と相手の関係をIDに混ぜている。端末によって同じ人の呼び名が逆になるうえ、3人目や複数端末を一貫して表せない。担当と操作者は追記専用の操作ログに保存されるため、単純な置換では過去ログのIDが壊れる。

## 決定

- メンバーは `mem_` 接頭辞付きの乱数IDを持つ。名前はIDと独立し、世帯内で共有する。
- この端末を使う人のIDは端末設定に保存する。表示では選択中の人を「自分」、それ以外を名前で示す。
- 各世帯に旧IDから新IDへの対応表を保存する。最初の同期で一度だけ対応付け、以後の端末も同じ対応を読む。
- 過去ログは書き換えず、射影時に旧IDを新IDへ読み替える。
- メンバーIDは本人認証ではない。ログイン・権限は別の仕組みとする。
- 既存端末に個別の名前変更があれば、旧IDの移行時に共有名簿へ送る。複数端末で名前が食い違う場合は、最後に同期した名前を採用する。

## 結果

世帯移行にサーバーの対応表が要るが、既存の担当・履歴・招待リンクを維持したまま参加者を増やせる。共有トークンの所持者は世帯メンバー情報を編集できるため、個別認証が必要になった段階で認可設計を追加する。
