# ADR 0004: 案件のメモ（詳細内・任意・「いま参照する情報」）

状態: 採用（実装済み。op 種別 `note`、`Issue.note`、詳細のメモ行、定期の引き継ぎ）

## 背景

電球の型番・管理会社の連絡先・提出書類の注意点をコメントだけに置くと、会話（経緯）に埋もれる。案件モデルには説明欄が無い（#57）。UI予算は「高度な機能は詳細の中に隠す」「ホームの情報量を増やさない」で、コメントは「これまでのやりとり（経緯）」を担う（[DECISIONS.md](../DECISIONS.md)）。メモは「いま参照する情報」として、経緯と分けたい。

## 決定

### 1. 置き場所と必須／任意

- 案件1件につき1つの「メモ」を持つ。任意・詳細内のみ。ホーム・一覧・通知には出さない。
- 追加は従来どおりタイトルだけ。メモは後から足せる。入力を必須にしない。
- 詳細の属性行（だれが／いつまで／くりかえし）と同じ並びに「メモ」の行を足し、押すと編集シートを開く。長文はシートで全文編集する。
- 新しい状態・新しい一覧・専用画面は作らない（1画面の主操作1つを守る）。一覧の行数・メタ最大2つは変えない。

### 2. 持ち方

- op 種別 `note`（`data.text`）。`text` は文字列。**空文字は「メモを消す」**。
- 同じ案件でいちばん新しい `note` が現在値（last-wins。[lib/sync/log.dart](../../lib/sync/log.dart) の `rename` と同じ扱い）。
- 履歴（「これまで」）には出さない（`rename` と同じ。値は専用の行に出るため、履歴に重複させない）。
- サーバーは op を解釈しないので**サーバー変更は不要**。wire は `note` を検証する（`text` は文字列のみ、他の型は受け付けない。[lib/sync/wire.dart](../../lib/sync/wire.dart)）。

### 3. 定期案件

- 「次を出す」で次の1件を生成するとき、いまのメモをコピーする（title・担当・期限と同じ）。型番のような固定情報が引き継がれる。
- 過去回はそれぞれ自分のメモを保持する（追記のみ＋案件ごとの射影）。過去回を開けば当時の型番が残る。
- メモを空にして完了した場合、次の1件のメモも空（消したものを勝手に復活させない）。

### 4. 同時編集

- 担当・名前と同じく last-wins（全順序: 論理時計 → 端末id → op id）。マージUIは作らない。
- 相手のメモ変更は通知しない（[0002-notification-policy.md](0002-notification-policy.md)）。

### 5. 削除・取り消し

- 案件を削除するとメモも一緒に見えなくなる（opは残るので復元は可能。ゴミ箱は作らない方針は据え置き）。
- 「取り消し」の専用操作は作らない。前の内容に戻すのは編集で上書きする。アプリのその場の取り消しは完了・再開が対象（変更なし）。

### 6. 個人情報

- メモは世帯に見える情報。「家族と共有」した場合は op としてサーバー（Cloudflare D1）に保存され、端末とサーバーのバックアップ（書き出し／復元）に含まれる。端末内の暗号化はしない（現行方針, [DECISIONS.md](../DECISIONS.md)）。
- ロック画面には出さず、OS通知の本文にも入れない（[0002-notification-policy.md](0002-notification-policy.md)）。電話番号・住所などを書ける点を [PRIVACY.md](../PRIVACY.md) の「記録の扱い」に追記する。

### 7. 既存データ互換

- 新しい op 種別 `note` を足す。既存案件はメモ無し（`null`）で、表示は「なし」。
- 旧IDの読み替え（`aliases`）や射影の規則は変わらない。古いクライアントは未知の `note` を落とすだけで、他の op の解釈には影響しない（wire の前方互換）。

## 代替案との比較

- **コメントの固定（ピン）**: 既存コメントを参照して上部に固定する案。経緯と現在情報の区別が曖昧になり、コメントの編集・削除・定期引き継ぎの意味づけが増える。「いま参照する情報」は1つで足りるので、専用フィールドの方が単純。
- **コメントのみ（見送り）**: 「情報が会話に埋もれる」がこのIssueの出発点。解決しない。

→ メモを採用する。

## 実装範囲と検証

- 範囲: `OpKind.note` と射影（last-wins）、`Issue.note`、詳細の属性行「メモ」と編集シート、定期の引き継ぎ、`wire` の検証、`PRIVACY.md` の追記。ホーム・一覧・通知・設定は変更しない。
- 検証:
  - ユニット: `note` op → 射影で現在値になる／空文字で消える／last-wins／定期の次件にコピーされる／過去回は自分の値を保つ／wire の往復（空文字を許容し、非文字列を拒否）。
  - ウィジェット: 詳細にメモ行が出る（無いときは「なし」）／編集して保存すると表示に反映／消去できる／ホームと一覧に変化が無い／文字拡大・小画面で崩れない。
- 検証: 上のユニット・ウィジェットを [test/issue_memo_test.dart](../../test/issue_memo_test.dart) に置く。`flutter test --concurrency=1` と `flutter analyze` を通す。

## 結果

- 詳細に任意のメモが1つ増え、経緯（コメント）と現在情報（メモ）を分けられる。ホームの情報量は増えない。
- 同期は op 種別を1つ足すだけで、サーバーは変更不要。定期案件で固定情報が引き継がれる。
- メモが世帯可視・同期・バックアップの対象であることを [PRIVACY.md](../PRIVACY.md) に明記する。

## 見直す条件

- メモに長文やリッチテキストを求めるようになったとき（非対象。今はプレーンテキスト1つ）。
- 写真・添付（#58）を採用するときは、メモとの住み分けをこのADRに追記する。→ 当面は見送り（メモで代替）。判断は [0005-photo-attachments.md](0005-photo-attachments.md)。
